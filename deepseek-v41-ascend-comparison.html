读懂本章全部术语 ↗
跨层共享 / source / consumer
Source 层生成某份可复用状态，consumer 层读取它，减少重复计算或存储。共享主 KV、共享 index K、共享候选块是不同关系；共享候选不代表各层最终选择的位置完全相同。
Indexer / index K
Indexer 是为长程注意力筛选历史位置的检索分支；index K 是它使用的键向量。它的维度、量化和共享关系可不同于主 KV，索引打分也不等于最终注意力打分。
vllm-ascend

能让多个层共用主 KV、索引键和候选范围。可以理解成“前面的层做好一份资料，后面的层继续用”，无需每层重新存一份。具体是谁提供、谁读取，由模型配置决定。

DeepInfer

也有主 KV、索引和候选范围的跨层共享。其构建器与运行状态对象负责记录共享关系，提供者和使用者同样要遵守模型配置。

实际影响

本章是共同原理说明，不计为功能差异。两边代码中对象名称、缓冲区归属不同，是移植时要核对的细节；不能据此声称共享更多、质量更高或更快。动画会特别说明：共用候选范围，不等于每层最终选中相同位置。

模型 / IMPLEMENTATION

C1/C2 压缩：两边都有，不能当成一边独有的能力

压缩器先把历史信息变成较紧凑的表示，后面的索引再决定重点看哪里。

共同能力本章解释共同原理，不把代码组织不同列为独有功能。
读懂本章全部术语 ↗
C1 / C2 压缩
在本报告所分析的压缩器中，C1、C2 对应压缩比 1、2：C1 不在位置数上减半，C2 将位置数约缩为一半。C2 的门控投影与状态更新是模型计算，不能用相邻向量的算术平均替换。
RoPE / pre-RoPE / post-RoPE
RoPE（Rotary Position Embedding）通过旋转向量编码位置信息。Pre-RoPE 表示旋转前，post-RoPE 表示旋转后。索引投影和主 KV 使用哪个阶段的向量，会影响数值与位置语义。
RMSNorm / 门控
RMSNorm 用向量的均方根进行归一化，再施加学习参数。门控用学习得到的系数调节信息流；“融合 norm / gate”指联合执行，不能省掉对应数学步骤。
vllm-ascend

实现 C1/C2 压缩和跨步状态维护。C2 会合并位置数，C1 不把位置数减半；投影、门控和状态处理均是模型计算的一部分。

DeepInfer

同样实现 C1/C2。代码把位置变换之前的压缩结果交给索引投影，并把位置变换后的结果写到主 KV；明确不接受 compression overlap 和 APE 两类配置。

实际影响

已确认的共同能力是 C1/C2。DeepInfer 对 overlap/APE 的拒绝是单侧限制；未证明 vllm-ascend 对同一 V4.1 配置提供可用支持，因此不列成“一边支持、一边不支持”。内核融合方式和中间数据存放位置也不单独列为功能差异。

稀疏注意力：两边都能“看近处，再挑重点看远处”

两边都有局部窗口与长程稀疏访问，底层调用不同不等于模型功能不同。

共同能力本章解释共同原理，不把代码组织不同列为独有功能。
读懂本章全部术语 ↗
MLA / latent
MLA（Multi-head Latent Attention）用较紧凑的潜在表示承载注意力信息。Latent 是学习得到的中间向量，并非原始文本摘要；本报告中的压缩 KV 必须结合 V4.1 的具体布局理解。
SWA · Sliding Window Attention
滑动窗口注意力只访问最近一段位置。例如窗口为 128 时，较早位置会离开局部窗口；长程压缩注意力仍可提供另一条访问历史的路径。窗口长度与压缩器环形状态行数是不同参数。
Q / K / V / logits
Q 是当前查询，K 是被查询的键，V 是承载聚合内容的值；Q 与 K 的匹配产生打分。Logits 泛指归一化前的分数：索引 logits 用于选位置，输出词表 logits 用于选下一个 token，不能混为同一张量。
vllm-ascend

局部窗口保留最近的信息，长程分支通过索引挑选历史位置，再计算注意力。不同昇腾硬件分支使用不同编码和算子接口。

DeepInfer

也通过索引筛选历史位置，再由主注意力使用选中的内容。索引打分、选取和注意力计算分别由相应底层库完成。

实际影响

从读者能使用的模型能力看，两边都有这条路径。需要单独看的实际差异是下一章的“哪些候选配置能选”，以及缓存章的“存多少字节、格式能否直接复用”。不能仅凭算子名字不同，断言一边支持的注意力更完整。

Top-k / candidate block / rerank
Top-k 取分数靠前的 k 项。Candidate block 先按块圈定较小的搜索范围，rerank 再在候选位置内打分筛选。块数、块内位置数与最终 top-k 数量是三个独立口径。

Source 层生成某份可复用状态，consumer 层读取它，减少重复计算或存储。共享主 KV、共享 index K、共享候选块是不同关系；共享候选不代表各层最终选择的位置完全相同。
QLI / QLI contract
本报告的 QLI 指 vllm-ascend 量化索引算子路径及其输入输出契约：例如 Q/K 编码、scale、候选块、输出索引顺序和无效位置填充值。它不是整个 Attention；通过 QLI 用例也不代表 DSpark、图执行或多机组合已通过。

Token 是分词或多模态处理后的序列单位，不固定对应一个汉字。Prefill 一次处理输入上下文；decode 在已有状态上逐步生成。二者的批量、访存和并行方式不同。
KV cache / HBM
KV cache 保存历史位置的注意力中间状态，避免生成每个新 token 时重算历史。V4.1 还涉及压缩 latent 与索引缓存；不能按普通 Transformer 的两份完整 K、V 直接估算。HBM 是计算卡上的高带宽显存。
FP4 / FP8 / INT8 / BF16
这些是存储或计算数值的编码。FP4、FP8 每值用 4、8 位浮点编码；INT8 用 8 位整数；BF16 用 16 位浮点编码。位数更低通常减小载荷，但精度和性能取决于 scale、算子及硬件。
Scale / block scaling / MXFP4
低位数值通常配合缩放系数 scale 还原范围。Per-16 表示每 16 个值共享一份 scale；MXFP4 是带块级尺度的 4 位浮点方案，不能把所有 FP4 格式都等同于 MXFP4，也不能只计算 4 位数据而漏算尺度。
E2M1 / E4M3 / UE8M0
这些后缀描述浮点指数与尾数布局：E2M1 常用于 FP4，E4M3 常用于 FP8；UE8M0 是无符号、无尾数的尺度编码。Scale 用 BF16、E4M3 或 UE8M0，会改变范围、字节数与内核接口。
ABI / layout / folded index
这里的 ABI 指算子之间传递张量的完整约定，包括 dtype、shape、步长、对齐、scale 排列和索引编码。Folded index 把多个索引位置折叠为一行；行大小不等于单位置大小。
W8A8 / checkpoint
W8A8 表示权重（W）和激活（A）使用 8 位量化路径，不表示 KV 一定也是 8 位。Checkpoint 是模型参数及相关配置快照；比较推理结果还要固定 tokenizer 和量化配置。

模型与状态

SWA · Sliding Window Attention
滑动窗口注意力只访问最近一段位置。例如窗口为 128 时，较早位置会离开局部窗口；长程压缩注意力仍可提供另一条访问历史的路径。窗口长度与压缩器环形状态行数是不同参数。
MLA / latent
MLA（Multi-head Latent Attention）用较紧凑的潜在表示承载注意力信息。Latent 是学习得到的中间向量，并非原始文本摘要；本报告中的压缩 KV 必须结合 V4.1 的具体布局理解。
C1 / C2 压缩
在本报告所分析的压缩器中，C1、C2 对应压缩比 1、2：C1 不在位置数上减半，C2 将位置数约缩为一半。C2 的门控投影与状态更新是模型计算，不能用相邻向量的算术平均替换。
RoPE / pre-RoPE / post-RoPE
RoPE（Rotary Position Embedding）通过旋转向量编码位置信息。Pre-RoPE 表示旋转前，post-RoPE 表示旋转后。索引投影和主 KV 使用哪个阶段的向量，会影响数值与位置语义。
RMSNorm / 门控
RMSNorm 用向量的均方根进行归一化，再施加学习参数。门控用学习得到的系数调节信息流；“融合 norm / gate”指联合执行，不能省掉对应数学步骤。
Indexer / index K
Indexer 是为长程注意力筛选历史位置的检索分支；index K 是它使用的键向量。它的维度、量化和共享关系可不同于主 KV，索引打分也不等于最终注意力打分。
Top-k / candidate block / rerank
Top-k 取分数靠前的 k 项。Candidate block 先按块圈定较小的搜索范围，rerank 再在候选位置内打分筛选。块数、块内位置数与最终 top-k 数量是三个独立口径。
跨层共享 / source / consumer
Source 层生成某份可复用状态，consumer 层读取它，减少重复计算或存储。共享主 KV、共享 index K、共享候选块是不同关系；共享候选不代表各层最终选择的位置完全相同。
mHC / lazy post / HCLazyPostData
mHC 管理多路残差流之间的混合与信息传递。Lazy post 将部分后混合推迟执行；HCLazyPostData 保存所需的残差与混合状态。裁剪 token 时，这些状态也必须同步裁剪。
MoE / gate / grouped GEMM
MoE（Mixture of Experts）由路由器为 token 选择少量专家。Gate 决定去哪些专家及其权重；grouped GEMM 把多个专家的矩阵乘法成组执行，以适应各专家 token 数不齐的情况。
Engram / n-gram
N-gram 是相邻 n 个 token 的组合。此处 Engram 根据 token 历史做 n-gram 哈希查表，再投影并门控注入 hidden state；它是模型记忆表路径，与保存注意力历史的 KV cache 不同。
DSpark / MTP / speculative decoding
推测解码先由草稿路径提出多个未来 token，再由目标模型验证。MTP（Multi-Token Prediction）为多 token 预测提供模型路径；DSpark 在本报告中还涉及置信度头与草稿/验证调度。
Confidence / verification / acceptance
Confidence 是草稿的置信度信号，可用于安排验证工作量；verification 是目标模型按相应规则验证；acceptance 是实际接受结果。高置信度不能保证被接受，接受率也不能直接换算成加速比。
Rollback / backtrack
草稿被拒绝时，需要撤销不应保留的位置与状态，使后续生成与正确的已接受前缀一致。回退不仅涉及 token 列表，还涉及 KV、压缩器、SWA、Engram 历史及辅助残差状态。
YOCO / bounded replay / compaction
YOCO（You Only Cache Once）相关路径让后段层复用前段生成的 KV。有界回放利用共享 KV 和局部窗口，将后段计算限制在必要后缀；compaction 是把相关 token 行与辅助状态一同裁紧。它不表示整个模型只计算后缀。
Prefix caching / paged KV / chunk
Prefix caching 在兼容条件下复用相同前缀的已算状态；paged KV 按块组织和分配缓存；chunk 把长输入分段处理。三者解决复用、分配和执行粒度问题，不能互相替代。
Hidden state / residual stream
Hidden state 是某层当前持有的 token 表示；residual stream 是跨子层传递并参与残差混合的状态。位置裁剪时，hidden 与残差/混合辅助状态必须使用一致的 token 行映射。
Q / K / V / logits
Q 是当前查询，K 是被查询的键，V 是承载聚合内容的值；Q 与 K 的匹配产生打分。Logits 泛指归一化前的分数：索引 logits 用于选位置，输出词表 logits 用于选下一个 token，不能混为同一张量。

并行与运行时

Dispatch / combine / all-gather
Dispatch 把 token 送到选中专家所在设备，combine 将专家结果汇回并合成。All-gather 把组内各设备的分片收集成完整数据。它们对应不同通信边界，不能统一视为“专家计算”。
EPLB / redundant expert
EPLB 是专家并行负载均衡：根据负载调整专家的物理分布或副本使用。Redundant expert 是热门逻辑专家的额外物理副本，不是新增一个不同的模型专家。
CPU offload / host registration / UVA
CPU offload 把部分数据留在主机内存，计算卡按需访问。Host registration 注册主机内存；UVA 是统一虚拟地址视图。可被设备寻址不代表拥有 HBM 的带宽与延迟，访问仍经过主机互联。
TP / DP / PP
TP（张量并行）拆同一层的张量计算；DP（数据并行）让多个副本处理不同请求或数据；PP（流水并行）把不同模型层放到不同阶段。具体 DP 含义还要看 Attention 与 MoE 的分组。
CP / balanced CP / PCP / DCP
CP（上下文并行）把同一序列的位置分给多卡；balanced CP 旨在平衡不同位置的计算量。PCP、DCP 分别对应 prefill、decode 阶段的上下文并行，组大小与支持限制可能不同。
EP / SP
EP（专家并行）把专家分布到多卡，需要跨卡派发 token。SP（序列并行）让部分激活按序列维度分片，常与 TP 配合；不能仅凭名称把它等同于 Attention 的 CP。
Eager / graph capture / graph replay
Eager 逐次发起算子执行；图捕获记录可复用的设备执行序列，图回放减少重复发起开销。动态形状与行映射仍需正确处理；图回放没有消除注意力或专家的数学计算。
Kernel fusion / profiling / warmup
算子融合把多个步骤合入较少内核，以减少发起或中间访存。Profiling 在此包括运行时显存预算测量；warmup 是预热与准备执行路径。预热时的行号不能被编译器错误固化为真实批次的行号。
异步调度 / MRV2
异步调度尝试让 CPU 的下一批准备工作与设备当前批执行重叠。MRV2 指 vLLM 的 Model Runner V2 执行路径，负责模型运行及其元数据接入；它不是新的模型结构。
VE / P-D disaggregation
VE 是视觉编码阶段；P、D 分别是 prefill 与 decode。分离部署把这些阶段放到不同执行资源，需要状态传输、路由和负载均衡。模型里有视觉编码器或 KV 管理器，不等于分离服务已完整交付。
TTFT / TPOT / SLO
TTFT 是请求到首个输出 token 的时间，需注明是否计入排队；TPOT 常指首 token 之后的平均每 token 时间。SLO 是服务目标，例如在延迟门限内达到的吞吐；脱离并发与延迟约束的峰值不能直接比较。

算子与验证

FlashMLA / DeepGEMM / DeepEP / DeepSelect
本报告中它们分别承担 MLA 注意力、矩阵乘法或索引 logits、专家并行通信、top-k 等选择操作。它们是不同环节的底层实现；DeepInfer 的 Ascend 依赖由平台分支选择，库名相同不代表直接执行 NVIDIA 内核。
TileLang / TileKernels
TileLang 是描述和生成分块计算内核的编程工具；TileKernels 是内核集合。本报告关注它们承担的压缩、归一化、位置变换、编码与写缓存等步骤；“使用同一工具”不能证明两仓的算子数值或性能相同。
QLI / QLI contract
本报告的 QLI 指 vllm-ascend 量化索引算子路径及其输入输出契约：例如 Q/K 编码、scale、候选块、输出索引顺序和无效位置填充值。它不是整个 Attention；通过 QLI 用例也不代表 DSpark、图执行或多机组合已通过。
Batch-invariant / deterministic sampling
Batch-invariant 追求同一输入的结果不随拼批方式改变；deterministic sampling 追求固定输入、参数与种子时采样可复现。它们比“固定随机种子”要求更多；DeepInfer README 将这两项明确限定为 NVIDIA，不能外推成 Ascend 支持。
