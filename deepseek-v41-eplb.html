如何读 L0 / L1 映射

L0、L1 是本例中两层待更新的 MoE 层。每层独立维护物理槽到逻辑专家的映射、逻辑专家到物理副本的映射，以及副本数。V0 是该层本轮更新前的布局，V1 是提交后的布局。两层同为 V1 时，各自的专家布局仍可以不同。

时间线记录步末状态。 当某步结束后显示 V1 / V0，下一次 forward 经过 L0 时使用新布局，经过 L1 时继续使用旧布局。后台的「就绪」表示权重已进入接收缓冲区。Runner 安装权重并刷新该层设备查表后，新布局才会生效。

例如，L0 的 P8 原先放 E7，V1 计划在 P8 放 E0 的副本。搬运期间，L0 的路由仍按 V0 使用 P8。提交 L0 后，后续 forward 才能把 E0 的部分 token 发往 L0 的 P8。L1 继续按自己的映射路由。

采样与触发

window_size 默认 1000，限制最近负载样本的环形窗口。step_interval 默认 3000，控制何时尝试重排。常规周期只在后 1000 步采集。dummy step 推进间隔计数但跳过普通样本写入。首次触发会提前，源码把计数器预置为 step_interval - step_interval // 4。

缓冲区与发布顺序

触发时准备负载快照，后台生成布局并把专家权重与相关量化张量移入接收缓冲区。所有 EP rank 就绪后，runner 在 forward 边界安装该层权重、提交映射、原地刷新设备查表，再确认缓冲区可复用。旧周期尚未提交完时，新周期延后。

P / D 节点的 step 怎么算

一次批次迭代记作 1 step。以下按 DP 均匀分配、持续满载估算，128k=131072、1k=1024 token。

P 节点：step ≈ 总请求数 × 未缓存输入 token ÷（DP 数 × 每 DP 每步 token 预算），向上取整。
本例缓存命中 0%，DP4、预算 8192：64 × 131072 ÷（4 × 8192）= 256 步。并发 8 即约 2 条请求 / DP，二者共享 8192 token 预算。

D 节点：step ≈ 请求波数 × 每请求解码轮数，即 ceil[总请求数 ÷（DP 数 × 实际 batch）] × ceil[剩余输出 token ÷ 每轮接受 token]。
本例 DP16、并发 144，实际 batch≈9 / DP；576 请求共 4 波。普通解码每轮接受 1 token：4 × 1024 = 4096 步；DSpark 若每轮均接受 6 token，则约 4 × 171 = 684 步。

D 的缓存命中 100%，128k 输入不重复计入稳态解码；若首 token 已生成，剩余输出改为 1023。上述为业务步数估算，预热、dummy 和调度差异会影响实际 EPLB 计数。

时间桶如何压缩负载窗口

时间桶是 window_size 负载窗口中一段连续、按推理步排序的样本。STAIR 将当前的 N 个样本切成 min(N, load_window_bins) 段。load_window_bins 默认 64，控制压缩后的段数上限。每个桶用各层、各专家的平均负载和桶内样本数参与后续计算。

相对阈值与绝对阈值的可调动画

专家负载观测

启用 EP 和 EPLB 后，在 --eplb-config 中设置 log_balancedness 和 log_balancedness_interval。前者默认 false，后者默认 1 且必须为正整数。已有 EPLB 配置时，把这两个字段合并到原 JSON。

--enable-expert-parallel \
--enable-eplb \
--eplb-config '{"log_balancedness":true,"log_balancedness_interval":10}'

当前步实测　EP rank 0 按日志间隔输出 EPLB step。每个 MoE 层先按 rank 汇总物理专家的实际命中数，再分别取 rank 平均值与最大值。avg_tokens 是各层平均值之和，max_tokens 是各层最大值之和。

balancedness = avg_tokens ÷ max_tokens。例如，两层的 rank 负载分别为 [120, 80] 和 [80, 120]，则 (100 + 100) ÷ (120 + 120) ≈ 0.8333。越接近 1 越均衡，max_tokens 为零时记 0。

负载输入把物理槽的命中数归并到逻辑专家后，使用每个专家在整个窗口的累计负载。按时间把相邻样本压成带权桶，从每个桶的专家均值及样本数估算均值、方差和专家间协方差。物理命中数按步归并到逻辑专家，经 EP all-reduce 得到 [step, layer, expert] 负载。
冗余副本每加一个副本，选 窗口累计负载 ÷ 当前副本数 最大的专家。用 (均值 + z × 标准差) ÷ 副本数 排序和估价，搜索多种副本预算分配，包括从当前副本数出发的增量方案。逐一尝试把下一副本给各逻辑专家，选择让 Σ步 max专家(该步负载 ÷ 副本数) 最小的专家。
放置目标按每副本累计负载降序投入当前最轻且未满的 rank。拓扑允许时，先把专家组打包到节点，再在节点内复制和放置。按单副本风险降序。优先选择放入后风险最低的可行 rank，风险包含与已有专家的协方差。每个 rank 至多放同一专家的一个副本，并检查迁移预算。按每副本累计负载降序。每试放一个 rank，就计算 Σ步 max rank(该步负载)，在未满的 rank 中选和最小者。
提交与搬运策略在配置周期计算布局。传入旧映射时，策略可保留同 rank 的原槽，权重搬运由上游 EPLB 执行。有有效基线时先看相对或绝对门槛。候选的预测平均峰均比和 p95 均需不劣于当前布局。Ascend MRV2 逐层异步搬运并提交。到重排周期后，在同一路径中执行规划、原位 shuffle，再更新物理到逻辑映射、逻辑到物理映射和副本数。

DeepInfer 怎样算逐步峰值和？

同一个无冗余算例中，试放 E3 时，rank 0 已有 E2 [100, 60, 140]，rank 1 已有 E0 [100, 120, 20]。E3 的三步负载是 [140, 70, 0]，E1 尚未放置。

候选得分 = Σ 每个采样步的最忙 rank 负载
先把试放专家的负载加到目标 rank，再逐步取各 rank 中最大的负载，最后把这些最大值相加。
